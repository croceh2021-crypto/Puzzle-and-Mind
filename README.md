# لغز وذكاء – PUZZLE & MIND

لعبة Android عربية تجمع بين الألغاز الذهنية واكتشاف الاختلافات بين صورتين. المشروع مبني باستخدام Godot 4.4.1 وCompatibility Renderer.

## الحالة الحالية
هذا المستودع يحتوي على نموذج أولي مبكر، وليس إصداراً نهائياً:
- واجهة رئيسية عربية عمودية.
- عالمان منفصلان: الألغاز الذهنية واكتشاف الاختلافات.
- 25 لغزاً ذهنياً محفوظاً في JSON.
- عالم اختلافات يضم 25 زوجاً من الصور؛ المرحلة الأولى تستخدم صورتين واقعيتين مع سبعة مواضع اختلاف، والمراحل الأخرى حالياً رسومات SVG تجريبية.
- حفظ محلي أولي للعملات والنجوم وتقدم كل عالم.

## المتطلبات
- Godot 4.4.1.
- Android export templates وAndroid SDK/Java عند إعداد تصدير APK.

## فتح المشروع
افتح مجلد المستودع في Godot 4.4.1، ثم شغّل المشهد الرئيسي `Main.tscn`.

## الفحص الآلي
يوجد Workflow في `.github/workflows/godot-check.yml` لفحص استيراد المشروع وتشغيل المشهد دون واجهة رسومية عند كل push أو pull request إلى main.

## ما لم ينجز بعد
- لم يتم بعد اختبار تشغيل Godot فعلياً في بيئة التطوير التي أنشأت النموذج.
- تم بناء Android Debug APK بنجاح عبر GitHub Actions والتحقق من سلامة ملف APK؛ لم يُختبر التثبيت على هاتف فعلي بعد.
- تم إعداد `export_presets.cfg` وتفعيل استيراد ETC2/ASTC اللازم لتصدير Android.
- أول مرحلتين من عالم الاختلافات تستخدمان صوراً من المستودع؛ بقية المراحل ومحتوى 300 مرحلة لم تُنتج بعد.

راجع `DEVELOPMENT_LOG.md` و`TEST_REPORT_2026-11-25.md` و`DESIGN_DECISIONS.md` لمعرفة القرارات والاختبارات وحدود النموذج.

## Android debug build
The repository now includes an Android export preset and a GitHub Actions workflow at `.github/workflows/android-debug.yml`. It attempts to build a signed debug APK using a temporary CI-only debug key and uploads the APK as a 14-day workflow artifact. This is a test build, not a Play Store release. Check the workflow run and its artifact before installing.


## اختبار Android Emulator
اختبار محاكي Pixel 2 اختياري ويُشغّل عند تشغيل Workflow يدوياً. يبني APK منفصلاً لمعمارية x86_64، ثم يثبته ويجمع لقطات شاشة وسجلات Android. لا تعتبر الاختبار ناجحاً قبل اكتمال المهمة وفحص الأدلة.


## تحسين حجم APK
تم استبعاد صورتين غير مستخدمتين حالياً من تصدير Android فقط عبر `exclude_filter`: `IMG20261022174658.jpg` و`IMG20261022174713.jpg`. بقيتا محفوظتين في المستودع لاستخدام مستقبلي. لم تُخفض دقة الصور المعروضة داخل اللعبة. يجب مراجعة نتيجة GitHub Actions وحجم APK الجديد قبل اعتماد مقدار التوفير.

### نتيجة تقليل حجم APK
استُبعد ملفا الصور غير المستخدمين من تصدير Android فقط. بناء GitHub Actions رقم `45703489969` نجح وأنتج APK بحجم 30,827,196 بايت (نحو 29.4 MiB)، مقارنة بحجم سابق يقارب 42.8 MB؛ توفير تقريبي 12 MB (نحو 28%). جرى فحص سلامة APK وأكدت قائمة المحتويات بقاء الصور المستخدمة واختفاء الملفين المستبعدين. لم تتغير دقة أو جودة الصور المستخدمة. اختبار المحاكي كان لا يزال جارياً وقت آخر توثيق.

## تدقيق Android وإصلاح اختبار التوافق – 2026-11-26
تم فصل تصدير الهاتف ARM64 عن تصدير المحاكي x86_64. يستخدم اختبار GitHub Actions الآن APK مخصصاً للمحاكي على Android API 34، ويضيف فحصاً للصورة الرئيسية لاكتشاف الشاشة الفارغة/الرمادية. هذا يمنع خطأ عدم تطابق المعمارية الذي كان موجوداً في إعداد الاختبار السابق. لا تعتبر المشكلة على الهاتف محلولة حتى تكتمل نتيجة المحاكي وتجربة APK ARM64 على جهاز OnePlus 9.


## تصحيح نتيجة التدقيق – السبب الجذري للشاشة الرمادية
- أظهر فحص سجل Godot التفصيلي لاحقاً خطأ Parse Error لمتغيري local وtarget في Scripts/main.gd (السطران 387 و393): تعذر استنتاج النوع تلقائياً. كان workflow القديم يسجل نجاح المهمة رغم رسائل الخطأ لأن أوامر Godot قد تنتهي برمز خروج صفر بعد فشل تحميل السكربت.
- تم إصلاح السطرين بإعلان النوع Vector2 صراحةً، حتى يستطيع Godot تحميل سكربت اللعبة عند بدء التشغيل.
- تم تعديل godot-check.yml لالتقاط مخرجات الاستيراد والتشغيل وفشل CI صراحةً عند وجود SCRIPT ERROR أو Parse Error أو فشل تحميل السكربت.
- هذا هو السبب البرمجي المؤكد الذي يطابق عرض الشعار ثم الشاشة الرمادية. لا نعتمد الإصلاح نهائياً حتى ينجح الفحص الصارم وتشغيل Android Emulator بعد التعديل.
